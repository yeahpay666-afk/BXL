用户 · 角色 · 权限 · 岗位 标准关联关系

柏星龙业务数字化中台 · 权限体系设计文档 · 2026-08-26

一、总体架构

权限体系采用 RBAC + 岗位 模型，通过"用户 → 岗位 → 角色 → 权限 → 应用"五层链路实现权限控制。岗位作为用户与角色之间的桥梁，实现人员变动时只调岗位不调角色。

核心链路：用户分配岗位 → 岗位绑定角色 → 角色配置权限 → 权限针对具体应用。用户通过岗位间接继承角色权限，不直接绑定角色。

二、实体定义

👤
用户 (User)

  • 系统中的实际使用者，对应具体员工
  • 属性：姓名、工号、部门、岗位
  • 一个用户只能属于一个岗位
  • 权限来源：通过岗位间接继承角色权限
  • 示例：张建国 → HR经理岗位

💼
岗位 (Position)

  • 组织架构中的职位，是角色的容器
  • 属性：岗位名称、编码、所属部门
  • 一个岗位可绑定多个角色（1:N）
  • 自动包含默认角色"基础用户"
  • 示例：HR经理 → [HR管理员, OA审批人, BI查看者]

👑
角色 (Role)

  • 权限的集合，是权限配置的载体
  • 属性：角色名称、编码、可访问的系统、数据范围
  • 一个角色可被多个岗位绑定（N:M）
  • 一个角色可针对多个应用配置权限
  • 示例：HR管理员 → 可访问HR系统 + 菜单/按钮/字段权限

🔐
权限 (Permission)

  • 四级粒度：菜单 → 按钮 → 数据行 → 数据列
  • 菜单权限：控制可见的菜单页面
  • 按钮权限：控制页面内的操作按钮
  • 数据行权限：按组织架构控制可见数据范围
  • 数据列权限：字段级控制（不可见/不可更改/部门可见脱敏）

三、关联关系矩阵

关系 基数 说明 维护入口
用户 → 岗位 N:1 一个用户属于一个岗位，一个岗位可有多个用户 用户管理 → 分配岗位
岗位 → 角色 N:M 一个岗位绑定多个角色，一个角色可被多个岗位引用 岗位管理 → 关联角色
角色 → 权限 1:N 一个角色拥有多套权限配置（按应用分） 角色管理 → 配置权限
角色 → 应用 N:M 角色配置"可访问的系统"，决定顶部导航可见性 角色管理 → 可访问的系统
权限 → 应用 N:1 每套权限配置针对一个具体应用 权限配置 → 选择业务系统
岗位 → 默认角色 1:1 所有岗位自动包含"基础用户"角色，不可取消 系统内置，不可配置

四、标准配置流程

1

应用管理：注册业务系统

在「应用管理」中新增业务系统（T100/HR/OA/CRM...），配置系统名称、编码、API地址。系统内置"全部系统"作为中台自身。

2

角色管理：创建角色并配置权限

在「角色管理」新建角色，设置"可访问的系统"（影响顶部导航），点击"配置权限"进入权限配置页，针对每个应用分别配置菜单/按钮/数据行/数据列四级权限。

3

岗位管理：创建岗位并绑定角色

在「岗位管理」新建岗位，选择所属部门（三级组织架构树），勾选该岗位包含的角色。系统自动包含"基础用户"默认角色。

4

用户管理：分配岗位

在「用户管理」为用户分配岗位，用户自动继承该岗位绑定的所有角色权限。支持按岗位批量分配。

5

权限生效

用户登录后，系统根据 岗位→角色→权限 链路计算最终权限集合，控制顶部导航可见性、菜单可见性、按钮可操作性、数据可见范围和字段脱敏。

五、权限四级模型

层级 控制对象 配置方式 示例
L1 菜单 页面可见性 树形三态复选框，父→子联动 勾选"员工档案" → 用户可见该菜单
L2 按钮 操作权限 按菜单分组，每个按钮独立勾选 勾选"新增" → 用户可点击新增按钮
L3 数据行 数据范围 5种范围：全部/本部门/本部门及下属/本人/自定义规则 选"本部门" → 只看到本部门员工数据
L4 数据列 字段级控制 三选一：不可见 / 不可更改 / 部门可见(脱敏) 设"手机号"为部门可见 → 显示 138****5678

六、特殊规则

6.1 默认角色机制

"基础用户"（ROLE_BASE_USER）是系统最低权限角色，所有岗位自动包含且不可取消。权限范围：门户首页访问、集团新闻/公告查看、个人信息维护。任何用户登录后至少拥有此权限。

6.2 "全部系统"选项

角色配置"可访问的系统"时，"全部系统"为聚合选项。选中后自动勾选所有具体系统（T100/HR/OA/CRM/SRM/BI/每刻报销）；选中任意具体系统时自动取消"全部系统"。此配置影响的是顶部导航访问权限，业务中台自身的权限。

6.3 权限继承与合并

一个用户通过岗位可能继承多个角色，权限取并集（而非交集）。即角色A有"新增"按钮权限、角色B有"删除"按钮权限，则用户同时拥有新增和删除权限。

6.4 数据列脱敏规则

操作类型 效果 适用场景
不可见 字段完全隐藏 敏感字段如薪资、身份证号
不可更改 字段可见但只读 关键字段如工号、入职日期
部门可见(脱敏) 跨部门可见但脱敏显示 手机号 138****5678、邮箱 z***@xx.com

七、典型场景示例

场景：HR部门新员工入职

步骤 操作 结果
1 应用管理已注册 HR 系统 HR 作为可选应用出现在角色配置中
2 角色管理创建"HR管理员"角色，可访问系统选"HR"，配置菜单/按钮/数据权限 角色拥有 HR 系统的完整权限
3 岗位管理创建"HR经理"岗位，关联角色：HR管理员 + OA审批人 + BI报表查看者 岗位包含3个角色 + 默认基础用户
4 用户管理中新增员工"张建国"，分配岗位"HR经理" 张建国自动继承4个角色的全部权限
5 张建国登录系统 顶部导航可见：首页、HR、OA、BI；菜单可见 HR 系统下的员工档案等；数据范围限本部门；手机号字段脱敏显示

场景：员工调岗（从HR经理调为销售经理）

只需在「用户管理」中将该用户的岗位从"HR经理"改为"销售经理"，权限自动切换。无需逐个调整角色绑定——这是岗位模式的核心优势。
